# recordForge Editor Capability Matrix

> **Status:** Phase 0 baseline — updated to current branch
> **Scope:** Editor specification traceability against the current repository
> **Reference:** `recordforge-editor-specification.md`, `editor-ui-cursor-imrovement-plan.md`
> **Owner:** Editor implementation work

This matrix is the working source for deciding whether a capability is already usable, partially connected, state-only, misleading, or missing. Existing code is evidence of current behavior, not evidence that the feature meets the editor specification.

## Status Definitions

| Status              | Meaning                                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------------------- |
| Working baseline    | The behavior is connected end to end for the currently supported subset, but may still need release hardening |
| Partial             | A meaningful part exists, but an important UI, persistence, preview, export, or recovery path is missing      |
| State-only          | A schema or command can represent the behavior, but the user cannot complete the workflow                     |
| Misleading          | A visible control or path suggests support that the implementation does not provide                           |
| Missing             | No meaningful implementation exists                                                                           |
| Hardware-unverified | The code path exists, but Windows hardware/manual evidence is still required                                  |
