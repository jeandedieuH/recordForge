# RecordForge 2.3.7

## Improvements

- **No more double pointer in apps that draw their own cursor.** Some
  applications — CAD tools like AutoCAD are the common case — hide the
  system cursor and paint their own crosshair or pointer inside the window.
  RecordForge now inspects the captured cursor bitmap on Windows and Linux
  (Wayland): when the system cursor is fully transparent, the recording marks
  the cursor as hidden, so the editor preview and exported video show only
  the application's own pointer instead of a second arrow on top of it.
- **CAD pickboxes and precision crosshairs render correctly.** Centered
  custom cursors — the small squares and crosshairs used for precise
  selection in AutoCAD, Revit, and similar tools — are now classified as
  crosshairs instead of wait spinners or generic arrows, both for new
  recordings and when older sessions are reopened.

## Fixes

- **Reduced a macOS crash risk during recording.** Probing undocumented
  macOS cursor selectors could raise an exception the app could not catch
  and terminate it mid-recording. RecordForge now only queries documented
  system cursors; the extra cursor shapes introduced in 2.3.6 (column/row
  resize, zoom, help, move, cell, busy-clickable) fall back to the default
  pointer until Apple documents a safe way to read them.

## Internal

- Cursor capture now carries a `visible` flag derived from the cursor
  bitmap's ink coverage. On Windows, custom cursors are composited into a
  32-bit DIB via `DrawIconEx` and classified from their actual artwork, with
  results cached per cursor handle; on Wayland the PipeWire cursor metadata
  feeds the same check.
- Recorded shape kinds are normalized at resolve time in both the TypeScript
  and Rust cursor engines: legacy small, centered `wait` shapes are treated
  as crosshairs, while the real 32×32 wait cursor still maps to the hourglass.
