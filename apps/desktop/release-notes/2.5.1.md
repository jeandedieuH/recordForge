# RecordForge 2.5.1

## Highlights

- **Camera placement rework.** Dragging a camera on the canvas now snaps to
  edges, the centre and thirds with visible guides (hold Alt to disable).
  The inspector is reorganised into Placement, Shape, Style and Framing
  sections — anchor grid, size and margin, split controls, aspect ratio,
  border and shadow, and source framing — plus an Auto/Pinned badge showing
  whether the camera follows the smart default for the canvas ratio or a
  spot you placed. Custom placements survive aspect-ratio changes, and
  switching resolution (e.g. 2160p exports) scales geometry, borders and
  shadows correctly. During a picture-in-picture layout segment the bubble
  can be dragged to a custom spot on the canvas, and split-screen slots and
  corner radii now resolve identically in preview and export.

## Improvements

- **Motion blur on every export path.** Zoom and pan motion blur previously
  reached only the GPU compositor; the compatibility (FFmpeg) renderer now
  renders the same shutter blur, capped at five taps per segment where the
  compositor reaches sixteen. When a fast sweep would exceed the cap the job
  lists "Fast motion blurred with up to 5 taps instead of the compositor's
  16" under Rendered with simplifications.
- **Colors you pick are the colors you get.** Exports now parse the full CSS
  Color 4 syntax the preview accepts — `rgb()`/`hsl()`/`hwb()`/`lab()`/
  `lch()`/`oklab()`/`oklch()`/`color()`, alpha channels and named colors —
  for canvas backgrounds, overlay and gradient colors, text and cursor
  SVGs. Values that used to fall back to black or a default hue now export
  as shown.
- **Camera and mask previews survive GPU failures.** The color-grade/LUT and
  background-cutout canvas now reports its own health — if WebGL is missing,
  loses its context or fails a frame upload, the plain camera video stays
  visible instead of a black bubble. Pixelate and blur masks get the same
  fallback, a shader sampling fix keeps masked regions aligned with the
  video, and camera footage loads origin-clean so the grading canvas can
  always sample it.

## Fixes

- **Glass Loupe reaches exports.** Loupe zoom segments were dropped while
  the render plan was built, so the lens previewed correctly but never
  appeared in the exported video. It now renders on both the GPU and
  compatibility paths; on the compatibility path the glass rim is
  approximated and reported under Rendered with simplifications.
- **Camera AI model downloads work again.** The YuNet face-detection model
  was fetched from a URL that serves a Git LFS pointer instead of the model
  file, so downloads failed the integrity check. Downloads now use the
  correct host and reject pointer payloads with a clear error.

## Known issues

- The compatibility export renderer still draws b-roll at a fixed rect and
  camera layouts at their static position: animated layers and layout
  transitions are reported as render notes ("Rendered without …") rather
  than silently differing from the preview, and camera border and shadow
  hide during animated layout windows on that path.
- Projects stay compatible in both directions: 2.5.1 reads older projects
  and keeps writing the legacy pixel transform alongside the new camera
  frame, so files still open in 2.5.0 — the new placement controls are only
  available in 2.5.1 and newer.

## Internal

- ADR 023 replaces the pixel `ClipTransform` camera model with a persisted,
  resolution-independent `CameraClip.frame` resolved by a shared
  preview/export resolver (`resolveCameraFrame`). `transform` is still
  written as a pixel mirror so projects open in older builds, placement is
  stored as fractions of the canvas short edge, and `update-canvas` no
  longer rewrites camera geometry.
- `overlay-engine` gains `css_color`, a shared CSS Color 4 parser used by
  the cursor SVG and raster paths, canvas backgrounds, gradient stops and
  overlay colors so export resolves the same values the preview does.
- Loupe segments cross the render-plan boundary as `style: "loupe"` zoom
  segments via `resolveLoupes`; the compatibility renderer draws the lens
  and shutter-tap zoom/pan blur (`COMPAT_MAX_BLUR_TAPS = 5`, versus the
  compositor's 16).
- The camera grading/cutout WebGL canvas and the mask shader renderer
  report fatal GL failures so the preview falls back to plain video or CSS
  mask visuals; asset-protocol videos load with `crossOrigin="anonymous"`
  to keep canvases origin-clean.
- Model downloads reject Git LFS pointer payloads, and the YuNet spec
  points at `media.githubusercontent.com` because the `raw` host serves
  LFS pointers for opencv_zoo.
- New renderer-specific golden-frame fixtures (`golden/effects`,
  `golden/effects-gpu`) pin loupe and motion-blur parity per renderer.
