# RecordForge 2.3.9

## Fixes

- **No more white flash when recording windows appear.** The countdown
  capsule, capture boundary, floating toolbar, webcam self-view, region
  picker, and teleprompter are transparent windows — but the webview inside
  them kept its own white background until the page's styles loaded, so each
  one flashed a white rectangle the moment it opened. All auxiliary windows
  now start with a fully transparent background, so only their intended
  content is ever visible.
- **Busy icon buttons keep their shape.** An icon-only button in its loading
  state used to render the spinner next to its icon, overflowing the square
  and painting over neighbouring controls — most visibly in the recorder
  transport row. The spinner now replaces the icon for the duration of the
  action, while text buttons keep their label beside the spinner.
- **Loading state is exposed to assistive technology.** Busy buttons now
  report `aria-busy`, so screen readers announce that an action is in
  progress instead of a button that appears to do nothing.

## Internal

- Auxiliary windows set a `(0, 0, 0, 0)` background colour at creation —
  `transparent(true)` alone only affects the OS window, and Windows honours
  the webview background only when the alpha channel is fully zero — and
  stamp a `data-*` attribute on the document during initialization so
  window-specific styles apply before first paint.
- The `Button` loading behaviour is covered by render tests in
  `@recordforge/ui`.
