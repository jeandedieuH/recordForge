# RecordForge 2.3.8

## Improvements

- **See the actual capture target before you start.** The New Recording
  dialog now shows a real, downscaled still of the selected display, window,
  or region — grabbed once through the same capture path the recording will
  use — instead of a schematic diagram. Stills for every display are fetched
  in the background when the dialog opens, so switching monitors is instant,
  and a hover refresh button grabs a fresh frame. When a still cannot be
  captured (missing permission, a wedged device), the dialog quietly keeps
  its schematic card; a preview can never block a start.
- **A start capsule, not a black scrim.** The countdown is now a small badge
  pinned to the top of the capture target — countdown ring, source name, and
  a real Cancel button — so you keep seeing the content you are about to
  demonstrate. The outline of the capture area appears while the countdown
  runs, and the capsule ends with a brief "Recording" confirmation before
  handing off to the floating toolbar. Escape still cancels, and it now
  works reliably even as the main window minimizes.
- **Know exactly what the next take contains.** The dialog's footer
  summarizes the armed configuration at a glance: the source and its
  resolution, the microphone, system audio, and webcam. The start delay is
  adjustable inline next to the Start button instead of only in Settings,
  and the GPU path, Smart Zoom, and keystroke overlay settings live in a
  collapsed Advanced section that reports how many options differ from the
  defaults.
- **Disabled Start explains itself.** Instead of a tooltip you can never
  reach, the dialog states the reason inline — choose a source, connect a
  camera, free up disk space, or grant Screen Recording permission on macOS.
- **Floating toolbar respects the recorded monitor.** The transport bar now
  lands on the display being captured rather than always the primary one,
  and its compact mode shrinks to a small pill. Both the toolbar and the
  camera self-view can be turned off entirely in Settings.
- **No overlays baked into Linux recordings.** X11 cannot exclude an
  auxiliary window from a screen capture, so the floating toolbar, camera
  self-view, and capture frame are off by default on Linux (the tray menu
  and global shortcuts still drive the session) and can be opted back in
  from Settings.

## Fixes

- **Shortcut and tray starts no longer replay stale settings.** Pressing
  the global record shortcut or the tray's Start used to begin a session
  natively from the last quick config — resurrecting old device selections
  and skipping the countdown entirely. Both now run the exact same flow as
  the Start button: current selections, devices, and your configured delay.
- **A failed start is no longer silent.** If arming the capture fails after
  the dialog closes (a device grabbed by another app, a revoked permission),
  RecordForge restores the main window and shows a toast with a direct route
  back to the setup dialog.
- **Cancelling confirms nothing was captured.** Aborting during the
  countdown — via Escape, the capsule's Cancel button, or the record
  shortcut — now confirms with a "Recording cancelled" toast instead of
  leaving you guessing.
- **A stuck countdown can no longer block every future recording.** If the
  countdown surface dies mid-arm (crashed renderer, lost IPC), the prepared
  session is aborted automatically after a grace period instead of holding
  the recorder hostage until you found the tray's cancel entry.
- **Fewer camera device conflicts on start.** When a webcam or camera
  preview is live in the setup dialog, RecordForge now closes the preview
  and gives the driver a moment to release the device before FFmpeg opens
  it, instead of racing the capture start.
- **The compact toolbar no longer eats desktop clicks.** Its invisible
  transparent margin used to keep the full window width, swallowing clicks
  across the desktop; the window now shrinks to fit the pill.

## Internal

- Source previews are produced natively by `grab_source_frame`, which reuses
  the real screen-input plumbing (same backend selection, same DPI
  normalization, same region crop) with a bounded timeout, and are cached
  per capture rectangle for the session.
- Shortcut and tray actions are resolved through a single `ShortcutAction`
  state machine (request-start / stop / cancel / ignore) covered by unit
  tests; starts are delegated to the frontend via a
  `recording-start-requested` event, and deliberate aborts are reported back
  via `recording-start-cancelled`.
- The countdown watchdog aborts a session still armed `countdown + 15s`
  after it began, and auxiliary windows consult
  `overlays_hidden_from_capture()` before painting over the desktop.
