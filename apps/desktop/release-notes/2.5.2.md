# RecordForge 2.5.2

## Highlights

- **Rate RecordForge from inside the app.** The About page (Settings → About
  & Studio, or the sidebar About view) has a new "Rate RecordForge" card,
  open to Free and Pro users alike. Pick a star rating and optionally add a
  short written review and display name; submissions are moderated before
  approved ones appear as testimonials on the website. Only your rating,
  optional text and name, app version, OS, and license tier are sent —
  never recordings or device identifiers. After submitting, the card shows
  a thank-you state instead of asking again.
- **Updated Pro terms.** Pro Lifetime is now a flat **$50** one-time
  purchase (founder launch pricing is gone) covering **one device at a
  time** — the seat is movable: deactivate in Settings → License and
  re-activate on another machine. The Free tier of official builds is now
  scoped to **personal, non-commercial use**; commercial use requires Pro.
  This is a term of the official-build distribution — the GPL-licensed
  source remains free to build and use for any purpose, and Free export
  capabilities are unchanged.

## Known issues

- Review submission needs a connection to the review service; offline or
  unreachable submissions show an error toast and can be retried — nothing
  is queued locally.
- Written reviews appear on the website only after moderation, so there can
  be a delay between submitting and the testimonial going live.

## Internal

- `submit_review` Tauri command (`src-tauri/src/commands/review.rs`) posts
  to `POST /api/reviews` on the marketing site — the webview CSP blocks
  external fetches, so the request runs in Rust like the license client.
  `tier`, `appVersion`, and `os` are filled server-side so a crafted IPC
  call can't spoof a Pro badge; dev builds can point at a local server via
  `RECORD_FORGE_REVIEWS_URL`.
- `packages/contracts/src/review.ts` defines the shared submission schema
  (1–5 star rating, ≤600-char text, ≤60-char name, honeypot field); the
  website validates with it and forwards to the Convex `reviews` mutation,
  which stores rows as `approved: false` until curated in the dashboard.
- The `reviewSubmitted` settings key persists the post-submit state; it is
  registered in the settings allowlist.
- Licensing docs updated for the new terms: `PRO-LICENSE-TERMS.md`,
  `LICENSING.md`, ADR 015 revision note, README tier descriptions, and the
  in-app About/upgrade/license-settings copy. No entitlement enforcement
  changed — the Free 1080p cap and Pro feature gates are identical.
- Website-side additions (same commit): Convex `reviews` module with
  `submit`/`list`/`stats`, a review form and testimonials section on the
  marketing site, and updated pricing page copy.
- Workspace version bump to 2.5.2 across all packages; SECURITY.md support
  window now covers 2.5.x.
